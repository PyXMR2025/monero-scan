# Suggest `hw_reconnect` when hardware wallet HID communication fails during refresh
author: bas-kirill
created_at: 2026-08-16T08:56:13Z
status: closed

# Problem

When using a Ledger (or other HID hardware wallet) with `monero-wallet-cli`, refresh can fail with a low-level hidapi error that is hard to act on:
```
Error: refresh failed: unexpected error: Unable to send hidapi command. Error 128: hid_error is not implemented yet. Blocks received: 63447
```

Similar messages also appear for send/create-tx paths (`Unable to send hidapi command. Error 64: ...`).

From a user perspective this looks like a blockchain/sync failure. In practice it usually means the device session was lost (USB glitch, Ledger Live holding the device, Monero app closed/locked, cable/port issues, Ledger Wallet app opened), while blocks may already have been received successfully.

The CLI already has `hw_reconnect` (“Attempts to reconnect HW wallet”), which calls `reconnect_device()`, but nothing in the error text points users to it. Many people end up restarting the whole wallet/process instead.

There is already a similar UX pattern on unlock failure for HW wallets:

> Please ensure the HW wallet is connected and unlocked.

# Proposal

When `refresh` (and optionally transfer/cold-sign paths) fails on a HW wallet (`key_on_device()`) with a device/HID-related error (`hidapi`, `No device`, `Unable to open device`, etc.), append a short hint, for example:

```
Try 'hw_reconnect' after unlocking the device and opening the Monero app. Close other apps that may be using the device (e.g. Ledger Live), then run refresh again.
```

Suggested place: `simple_wallet::refresh_main` in `src/simplewallet/simplewallet.cpp`, in the existing `if (!ok)` fail path — not in `device_io_hid.cpp`, so GUI/RPC are not tied to a CLI command name.

Do **not** show this hint for unrelated failures (daemon busy / no connection to daemon).

# Why this helps

- Makes the recovery path discoverable without reading docs/`help`
- Reuses an existing command instead of adding a new one
- Matches the unlock-time HW guidance already in simplewallet

# Related

- Error originates from `src/device/device_io_hid.cpp` (`Unable to send hidapi command...`)
- Known reports: #7907, #9201, and similar Ledger disconnect-during-sync reports
