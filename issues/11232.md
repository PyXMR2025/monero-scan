# ringct: fuzz and harden Bulletproof verification
author: Ap4sh
created_at: 2026-09-02T14:26:31Z
status: open

the legacy Bulletproof fuzz target is already included in the current OSS-Fuzz build, but it only deserializes proofs and never reaches verification

this serializes commitments separately, restores `proof.V`, and calls `bulletproof_VERIFY()`. both fuzz targets pass malformed proof shapes directly to their verifiers

both verifiers now reject more than 16 commitments before deriving proof dimensions, preventing their fixed generator arrays from being indexed out of bounds. the legacy corpus covers valid proofs with 1, 2, 4, 8, and 16 outputs

tests:
- reproduced the `V.size() == 17`, `L/R.size() == 11` case as a global buffer overflow in both verifiers under ASan before the fix
- both regression cases are now rejected under ASan
- all 10 valid Bulletproof and Bulletproof+ seeds run under ASan
- 100k libFuzzer runs with ASan on each target
- `unit_tests --gtest_filter='bulletproofs.*:bulletproofs_plus.*:bulletproof.*'`
- full `unit_tests`: 1310 passed, 2 skipped
