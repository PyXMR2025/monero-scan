# No robustness against corrupted blockchain
author: throwedpower32
created_at: 2026-08-15T10:52:57Z
status: open

I was synchronising monero blockchain (using GUI) and for some reason it hanged at some point and the computer had to be rebooted (disk I/O error or something probably).

I started syncing again but the GUI complained that it could not connect to daemon.

I thought the blockchain database was corrupt so I deleted the database file data.mdb and now syncing is working again. It will just take time. But there are multiple issues:

First is lack of information given in the gui, or in the logs. The GUI only tells you that it can't connect to monerod. It doesn't tell what is happening in monerod. The log file (bitmonero.log if i'm looking at the correct file?) does not tell the reason for this either (monerod crashed, nothign about this in the log).

I ran monerod manually from terminal and finally got a hint: "Bus error (core dumped)". And this was a hint that the blockchain may be corrupt. 

Second is lack of robust salvage method for corrupt database. I used "monerod --db-salvage" but it didn't work and I received only error: "Failed to parse block from blob"

Third is susceptibility of the database to corruption and lack of resilience and robustness against corruption in general. There is one big database file and if just a bit of it gets corrupted (happens pretty easily) then it has to be downloaded and synced again.
