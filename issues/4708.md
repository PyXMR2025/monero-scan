# Feature request: Implement support for Shamir SLIP-0039 for a multi seed backup
author: EntropyHoover
created_at: 2026-09-13T10:01:42Z
status: open

Currently monero only supports a single seed backup method, which is susceptible to theft and loss. Shamir backup will generate multiple seed based on a private key, and allow user to recover the private key if the user hold enough shares above the threshold. [SLIP-0039](https://github.com/satoshilabs/slips/blob/master/slip-0039.md)

Currently trezor has an implementation in python [python-shamir-mnemonic](http://github.com/trezor/python-shamir-mnemonic/), which supports directly split a hex encoded key into shamir shares. It should work out of box for the backup purpose, just supply the private spend key generated to it and generate the shares. 
```bash
shamir create 2of3 --master-secret "<64-hex-private-spend-key>"
```

If the implementation has vulnerability, the security implication would still be limited. The script should only be invoked as a helper in wallet creation wizard to display seed, and when restoring the wallet. 
The possible problems are:
1.Fewer shares are required to restore the private key
2.More shares are required to restore the private key, or it cannot be restored.
For 2. the total share could be limited like 10, and do a combination brute force assert to make sure the same private key really comes back. For 1. actually requires a math audit.

If monero project consider directly using external code is unsafe, it could implement its own shamir module. The shamir algorithm did not need to be aware of monero protocol or its ED25519, which shouldn't bring extra complexity.
