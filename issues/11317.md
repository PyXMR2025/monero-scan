# wallet2: add user-facing skip-sync (--skip-sync-to-height) — analysis, patch proposal, test plan [bounty #79 ref]
author: Sitevo
created_at: 2026-09-13T18:35:48Z
status: closed

This is a proposal (analysis + patch sketch + test plan) for a skip-sync feature, motivated by a community bounty for data-saving wallet syncing on expensive/limited mobile data (context: users who *know* they received nothing since last sync shouldn't have to download ~500 MB of block bodies).

**TL;DR: the engine already supports skip-sync; this patch adds the missing user-facing switch (~120-150 LOC, no engine or cache-format changes).**

## Analysis (monero master @ 9e3a3103)

- `wallet2::refresh()` (src/wallet/wallet2.cpp:4068) already honors an internal `m_skip_to_height` (src/wallet/wallet2.h:1700, comment: "useful when we don't want to modify the wallet's restore height"). When it exceeds the local chain tip, refresh computes `start_height = max(m_refresh_from_block_height, m_skip_to_height)` (wallet2.cpp:4110-4112) and runs `fast_refresh()` (wallet2.cpp:3946), which pulls **only block hashes (~32 B/block)** up to the skip height (null-padding to checkpoints) and then pulls full blocks just from the tip onward. This is the 500 MB+/30+ min saving, already implemented.
- `m_skip_to_height` is **persisted** in the wallet cache JSON as `"skip_to_height"` (wallet2.cpp:4709 write / 5184 load), so no cache version bump is needed.
- `should_skip_block()` (wallet2.cpp:3021) also honors it to skip CPU-heavy scanning of below-skip blocks.
- Today it is set **only** automatically by `wallet2::scan_tx()` (wallet2.cpp:1959-1963). There is no CLI flag, no interactive command, no `set` variable, and no wallet-rpc method to set it — verified by grep across wallet2.{h,cpp}, simplewallet.cpp, wallet_args.cpp, wallet_rpc_server.cpp.
- Recovery of txs missed by a skip already exists: `scan_tx <txid>` (targeted, cheap; CLI simplewallet.cpp:2984 + RPC commands_defs.h:2107) and `rescan_bc` (full).
- The "sync by date range" variant is nearly free: `get_blockchain_height_by_date()` (wallet2.cpp:15159) already maps dates to heights.

## Proposed patch (sketch; full diffs in the linked artifact)

1. `wallet2.h`: public `set_skip_to_height(uint64_t)` / `get_skip_to_height()` next to `set_refresh_from_block_height()` (with a doc comment explaining the NOT-detected-txs caveat and recovery paths).
2. `simplewallet.cpp`: `--skip-sync-to-height <N>` flag + interactive `skip_sync_to_height [<height>|current]` command; validates against daemon height / local tip, sets it, and rewrites the wallet to persist immediately.
3. `wallet-rpc`: `skip_sync_to_height {height}` JSON-RPC method (mirrors `on_scan_tx`), so GUIs (Monerujo/Feather/Cake) can implement "Skip sync" / "Sync dates" / "import TX with scan_tx" buttons over RPC.

Design notes:
- Uses `m_skip_to_height` rather than bumping the restore height, per the upstream comment at wallet2.h:1701-1702 (restore height is the wallet's identity; skip height is a session/data-saving control).
- Safety: txs received in the skipped range are simply unknown — no key images/outputs are materialized, so they can't be spent or double-spent; recoverable via `scan_tx`/`rescan_bc`. On-chain privacy is unaffected (skipped data is never requested; hash pulls are generic and unavoidable).
- Edge cases to enforce: height > daemon height → reject; height below local tip → no-op; resets only on wallet generate/init (existing behavior, wallet2.cpp:4518/4537/5025), which is correct for a freshly generated wallet.

## Test plan (11 cases, testnet)

T1 baseline bandwidth; T2 skip via flag → hash-only fast_refresh + tail (assert order-of-magnitude byte reduction); T3 missed-tx semantics (tx below skip height NOT detected, wallet stays consistent); T4 `scan_tx` targeted recovery; T5 `rescan_bc` full recovery; T6 cache persistence across restart; T7 edge inputs (>daemon height, 0, below tip, offline); T8 reorg across skip boundary; T9 RPC flow; T10 date-range sync via `get_blockchain_height_by_date`; T11 interop with `scan_tx`'s detach/reprocess path.

Happy to develop this into a compile-verified PR if maintainers are open to the feature. Full analysis document with exact diffs and line-referenced deep-dive available on request.

Refs: community bounty discussion of this exact feature ("skip sync" with Skip sync / Sync dates / Full sync / scan_tx buttons); `scan_tx` upstream work is the model to follow.
