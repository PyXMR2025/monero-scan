# Include tx_hash in the cold-signing output export format
author: yagop
created_at: 2026-08-24T21:41:20Z
status: open

Since #11132, `incoming_transfers` returns an empty `tx_hash` string on an offline (cold) wallet, because the export blob from the hot wallet doesn't carry the txid. 

`exported_transfer_details` (`src/wallet/wallet2.h`) has no `m_txid`, so `import_outputs` sets it to `null_hash` (`src/wallet/wallet2.cpp`).

### Proposal

Add `m_txid` to the export format. The struct is already versioned, so this is backward-compatible:
- Bump struct version to 2, serialize `m_txid` when `version >= 2`.
- Set `etd.m_txid = td.m_txid` on export, restore it on import for v2 blobs.
- Old (v1) blobs import unchanged.

### Tradeoffs
- **Cost:** +32 bytes/output, unconditionally, in an air-gapped blob.
- **Benefit:** cold wallet can show the real hash — but only cosmetically; it can't
  verify or look it up, and the hot wallet already has it.
- **Design:** the cold side is sent the minimum needed to sign; this adds a field it
  can't verify.
