# Document the rpc_access_* daemon JSON-RPC methods
author: johnr365
created_at: 2026-06-04T20:34:39Z
status: closed

The RPC access methods (the pay-for-RPC / RPC-payment subsystem) are implemented but undocumented. Adds sections with inputs, outputs, and a real regtest-captured example for each of:

- `rpc_access_info` (`core_rpc_server.h:184`)
- `rpc_access_submit_nonce` (`:185`)
- `rpc_access_pay` (`:186`)
- `rpc_access_tracking` (`:187`)
- `rpc_access_data` (`:188`)
- `rpc_access_account` (`:189`)

Field names and types are taken verbatim from the request/response structs in `core_rpc_server_commands_defs.h` (the `COMMAND_RPC_ACCESS_*` definitions and their `rpc_access_request_base` / `rpc_access_response_base` / `rpc_response_base` bases, so `credits` and `top_hash` appear only on the methods that actually inherit them). Formatting follows the existing daemon JSON-RPC sections; no restricted/public annotation is added, matching the rest of the page.

The `rpc_access_info`, `rpc_access_pay`, and `rpc_access_submit_nonce` examples were captured against a regtest node with RPC payments disabled, so they show the payments-disabled response (zeroed fields / "Payment not necessary"); the documented input fields still come from the structs above. The `rpc_access_data` and `rpc_access_account` examples were captured against a second regtest daemon run with RPC payments enabled.
