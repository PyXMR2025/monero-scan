# common: exit child when execve fails
author: Ap4sh
created_at: 2026-09-12T22:48:55Z
status: open

when `execve()` fails after `fork()`, the child currently returns from `tools::spawn()` and continues running the copied wallet process with stdin and most file descriptors closed

exit the child immediately instead. this also avoids calling the C++ logger in the post-fork child

the regression test uses an executable script whose shebang interpreter does not exist, so `execve()` itself fails rather than the script returning a nonzero status

fixes #8864

tests:
- `cmake --build build-gcc -j2`
- `ctest --test-dir build-gcc -R "^unit_tests$" --output-on-failure`
- `env GTEST_FILTER="-DNSResolver.*:AddressFromURL.*:select_outputs.*" ctest --output-on-failure -E "functional_tests_rpc|core_tests|cnv4-jit|hash-variant2-int-sqrt|wide_difficulty"`
- `unit_tests --gtest_filter="notify.*" --gtest_repeat=50 --gtest_break_on_failure`
