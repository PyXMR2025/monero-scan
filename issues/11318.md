# cryptonote_core: handle future txpool times
author: Ap4sh
created_at: 2026-09-13T23:04:09Z
status: open

A backward wall clock adjustment can leave txpool entries with `receive_time` later than the current time

The unsigned age calculation would then wrap, which could remove fresh transactions as expired and produce out-of-range transaction pool histogram indexes

This clamps future receive times to the current time for cleanup and statistics, and adds a core test covering future and genuinely expired entries

Tests:
- `ctest --test-dir build-ci --output-on-failure -R '^core_tests$'`
