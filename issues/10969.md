# blockchain_utilities: resume interrupted exports safely
author: Ap4sh
created_at: 2026-07-24T22:57:29Z
status: open

an interrupted `monero-blockchain-export` write can leave the final chunk header or payload incomplete

the scanner previously used `seekg()` to skip each payload. seeking beyond EOF succeeds, so the incomplete chunk was counted as a complete block and the next export appended after the partial data, leaving later chunk boundaries misaligned

this checks chunk boundaries against the file size while scanning. when the only problem is an incomplete trailing chunk, the writer truncates back to the last complete chunk and resumes from that height. malformed chunk sizes and ordinary read errors still fail without modifying the file

this prevents the interrupted-tail corruption path described in #9352 and repairs exports that still end at the incomplete chunk. it does not try to recover a file that was already appended to and misaligned by an older resume

tests:
- importer and exporter targets with GCC 14 Debug/Release and Clang 19 Release
