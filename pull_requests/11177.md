# cryptonote_core: validate block sync size
author: Ap4sh
created_at: 2026-08-23T20:48:50Z
status: open

Manual `--block-sync-size` values above 100 exceed `CURRENCY_PROTOCOL_MAX_OBJECT_REQUEST_COUNT`, so peers drop the connection when the daemon requests blocks

This moves the protocol limit into the shared config and rejects oversized values during command-line handling, before the blockchain database is opened

This addresses the `>100` case in #9897. Values at or below 100 may still be constrained by serialized batch size, so this does not close the full issue

Tests:
- `cmake --build build --target daemon unit_tests -j2`
- `build/tests/unit_tests/unit_tests --data-dir tests/data` (1299 passed, 2 skipped)
- manual `monerod` checks with `--block-sync-size=0`, `100`, `101`, and `2049`
