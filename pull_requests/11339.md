# txpool: don't drop cxns relaying key images spent in chain
author: j-berman
created_at: 2026-09-18T00:04:44Z
status: open

Assume a reorg of Tx A out the chain back into the pool (or Tx A is just normally relayed to a node), and then a new Block B comes along that includes Tx B spending the same output(s) as Tx A.

Nodes currently will attempt to re-relay Tx A even though its output(s) are spent in the chain. If a node receives Tx A from another node, it will drop the connection ([1](https://github.com/monero-project/monero/blob/6bb36309d69e7157b459e957a9a2d64c67e5892e/src/cryptonote_core/blockchain.cpp#L3409-L3414), [2](https://github.com/monero-project/monero/blob/6bb36309d69e7157b459e957a9a2d64c67e5892e/src/cryptonote_core/tx_pool.cpp#L270-L273), [3](https://github.com/monero-project/monero/blob/6bb36309d69e7157b459e957a9a2d64c67e5892e/src/cryptonote_protocol/cryptonote_protocol_handler.inl#L940-L945)).

Since it's possible for an honest node that hasn't seen the new block B to attempt to relay Tx A to a node that has already seen Block B, this PR changes this to a no-drop-offense. The honest node's connection will continue processing any other txs the honest node relayed to it [here](https://github.com/monero-project/monero/blob/6bb36309d69e7157b459e957a9a2d64c67e5892e/src/cryptonote_protocol/cryptonote_protocol_handler.inl#L937-L962).

____

This was implemented on the beta stressnet [here](https://github.com/seraphis-migration/monero/pull/207) because we observed this issue causing dropped connections there in high frequency.

In line with #11091, I made sure to add this check **before** the more expensive verify in this PR.
