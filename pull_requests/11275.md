# wallet: add optional flush parameter preemptive of disaster events
author: ilike314272
created_at: 2026-09-09T03:51:40Z
status: closed

PR is in response to issue #11266 

The wallet's subaddress creation method does not write into the wallet cache file until the next `store()` but assumes the in-memory address has been written. Disaster events can lead to funds being directed to an address that does not exist on the computer, being rendered inaccessible. The next time a subaddress is created issues an index already handed out. Issue #3681 suffers from the same problem. 

An optional `flush` parameter allows existing code using the wallet program to still work or for performance guarantees to be kept for high-volume subaddress issuance use cases, and wallets will now be able to store the address before responding, so that the wallet exists even during a disaster event. Added a new `create_address_flush_case` case to the `wallet.py` to verify that the flush parameter works.
