# epee: reject ambiguous HTTP request framing
author: Ap4sh
created_at: 2026-09-10T11:02:54Z
status: open

Repeated `Content-Length` fields currently overwrite each other, while request `Transfer-Encoding` is stored even though the server never decodes it. This can make the request body boundary ambiguous or dispatch a transfer-encoded request without its body

Parse every `Content-Length` value before dispatch and only accept repeated decimal values when they resolve to the same length. Reject request `Transfer-Encoding` until it is supported

Tests:
- `cmake --build build --target all -j2`
- `unit_tests --data-dir tests/data --gtest_filter='HTTP*'`
- `unit_tests --data-dir tests/data`
- targeted tests under Valgrind
