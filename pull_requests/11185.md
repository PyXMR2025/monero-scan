# wallet_api: lock refresh around wallet mutations
author: Ap4sh
created_at: 2026-08-25T15:14:36Z
status: open

fixes #9332

`Wallet::store()`, `WalletManager::closeWallet()`, transaction creation, and transaction broadcast could run while refresh was mutating wallet state

suspend the active refresh, wait for wallet state to settle, perform the operation, then restore the previous auto-refresh state. synchronous refresh and rescan calls return false if an operation interrupts them, without emitting `refreshed()` for that attempt. queued rescans stay pending until they can run

calls that would re-enter the same wallet from a refresh callback return an error instead of deadlocking

tests:
- full GCC release build
- full `libwallet_api_tests` with GCC and Clang (50/50)
- 10 consecutive focused concurrency runs
- mutation checks against the previous behavior
- isolated `functional_tests_rpc` (19/19)
- `core_tests` (1/1)
