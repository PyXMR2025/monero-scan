# Fix two separate data races in async levin commands
author: vtnerd
created_at: 2026-08-18T00:57:16Z
status: merged

This cleans up the levin `weak_ptr` patch further by consolidating some of the logic and fixes two race conditions:

 * The `m_timer` object can be accessed by two different strands, which has been the case since basically forever.
 * The `m_con` object can be accessed by two different threads, which was introduced recently.

This adds a simple mutex to fix the issue, which was easier than a strand because of the design on cancelling the timer. The other option would be to leverage the strand in the connection object, EXCEPT two different strands are already used for `handle_recv` and `release_protocol`, thus the `mutex` is indeed the easiest.
