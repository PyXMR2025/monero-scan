# Fix garbled $1 field name in get_info/get_connections/hard_fork_info responses
author: johnr365
created_at: 2026-06-04T16:47:08Z
status: merged

Three daemon JSON-RPC response tables document a field literally named `$1` - the residue of a botched find-replace upstream. The real field is `untrusted` (the bootstrap-mode flag); the example payloads in these very sections already show `"untrusted": false`.

Renames the `$1` bullet to `untrusted` in:
- `get_info` response
- `get_connections` response
- `hard_fork_info` response

Source: `untrusted` is a member of `rpc_response_base` (`core_rpc_server_commands_defs.h`), inherited by all three responses. No content change beyond the field name.
