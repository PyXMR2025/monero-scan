# p2p: add Tor SOCKS stream isolation
author: EntropyHoover
created_at: 2026-09-05T07:21:57Z
status: open

This PR implement a feature that will ask tor client for isolated circuits. This is implemented by tor's SOCKS authentication isolation. It will supply a socks username \<torS0X\>0 and a 64 character random password for --proxy and --tx-proxy separately(if they are enabled). This will make sure tor connection from public zone and tor zone to have their isolated tor circuit. This will avoid sharing circuit with other connections and decrease the risk of identity correlation. [Stream Isolation](https://www.whonix.org/wiki/Stream_Isolation). This feature should also make monero gui being used in whonix to apply stream isolation by default easier to implement.

According to tor document [351-socks-auth-extensions](https://spec.torproject.org/proposals/351-socks-auth-extensions.html) connections without socks credential are considered as "same isolation group", and might share the tor circuit.

By default, if a user started monerod with 
```bash
monerod --proxy socks5://127.0.0.1:9050 --tx-proxy tor,socks5://127.0.0.1:9050
``` 
Connections might share circuits with other triaffic that did not properly configure stream isolation, if 9050 itself isn't configured with IsolateDestAddr and IsolateDestPort.

With --tor-stream-isolation, monero connections get their isolated circuit with different socks auth.
```bash
//Traffic from --proxy public zone connection use one socks credential
650 STREAM 1379 SUCCEEDED 1107 SOCKS_USERNAME="<torS0X>0" 

SOCKS_PASSWORD="b7a2a770d6a0ee9da41f3ec9ba866b44643524ccf8595613aa1492598dc93fc9" 

//Traffic from --tx-proxy tor zone connection uses another socks credential
650 STREAM 1380 NEW 0 hhna6x36ynss33iad6dfydlu7jzr4omuca3cj23lxmu2dxizfx3xf6id.onion:18083
PURPOSE=USER SOCKS_USERNAME="<torS0X>0" 

SOCKS_PASSWORD="d4280211d09894e9ab018dbf51b946d54e8acad1168342c2ca552c83468df226" 
```
